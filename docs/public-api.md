# 默认 C 端 API

`apps/api` 是一个独立运行的 NestJS + Fastify 应用。它不是管理 API 的子模块，也不依赖 `apps/admin-api`；两个服务只通过 `@repo/database` 和 `@repo/shared` 共享数据库模型与跨端契约。

## 为什么默认保留这个服务

具体 C 端可能是小程序、SSR 官网、单页应用或移动端，仓库不会提前创建任何虚构客户端和业务页面。但健康检查、字典读取和非敏感公共配置读取在大量 C 端项目中都可以复用，因此默认服务同时承担两项职责：

1. 提供可以直接使用的基础公共能力；
2. 展示一个新业务服务应遵守的 NestJS 模块、数据库、配置、测试和错误处理方式。

即使真实业务暂时不用字典或公共配置，这三个小模块也不会改变项目架构，更不会把仓库变成某一种 C 端产品。

## 已有接口

| 方法 | 地址                             | 鉴权 | 说明                           |
| ---- | -------------------------------- | ---- | ------------------------------ |
| GET  | `/api/health`                    | 无   | 进程健康检查                   |
| GET  | `/api/public/dictionaries/:code` | 无   | 按编码读取启用字典和启用字典项 |
| GET  | `/api/public/configs/:key`       | 无   | 按键读取单条公共配置           |

公共接口不存在“读取全部配置”的能力。字典停用后，或字典项停用后，对应数据不会进入公共响应。

## 安全边界

公共配置中的全部值默认对未登录用户可见，管理页面和代码注释都会明确提示这一点。这里可以保存站点名称、客服邮箱、协议版本、公开开关等数据，不能保存：

- 数据库密码；
- JWT、OAuth 或第三方平台密钥；
- 对象存储 Secret；
- 内网地址与内部连接串；
- 任何只应由服务端读取的配置。

服务端私密配置继续由环境变量或部署平台 Secret 管理。

## 本地开发

执行 `pnpm setup` 会同时生成 `apps/api/.env.development` 和 `apps/admin-api/.env.development`。默认 C 端 API 使用端口 `3001`：

```bash
pnpm dev:api
```

创建真实 C 端后，应把 `apps/api/.env.development` 中的 `CORS_ORIGINS` 改成客户端实际开发地址。生产环境则由部署平台注入 `DATABASE_URL`、`CORS_ORIGINS` 和 `PORT`，不要提交真实环境文件。

## 扩展真实业务

业务仍在同一边界内时，直接在 `apps/api/src/modules` 下按领域新增 NestJS 模块。只有在独立部署、独立扩缩容、团队边界或故障隔离需求真实出现后，才使用 `pnpm new:server` 创建额外服务。默认存在两个可独立运行的 NestJS 应用并不等于微服务，当前仓库依旧没有网关、服务发现和分布式治理能力。
